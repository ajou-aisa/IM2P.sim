# Drained HP1 service certificate

`CycleServiceProvider` validates the current fixed-fixture drained boundary with an `im2p-drained-service-certificate` v1, the matching current single-work certificate, a production-generated run-aware certificate, and their exact cycle-library binary. The validator checks the independent service corpus, current source hashes, official RTL build bindings, raw logs, probe binaries, and the complete trace. The resulting provider scope is `DRAINED_FIXTURE_PARITY`; `admission` for production scheduling remains absent. A copied `CURRENT_CERTIFIED_SEQUENCE` string has no admission effect.

The supported scheduling scenario is one NPU with one outstanding work. The next work may start at or after the previous `resource_ready_cycle`; `result_ready_cycle` is earlier and does not release the resource. `im2p_cycle_estimate_service` carries the next scratchpad and accumulator halves. The trace must use the current v2 planner-block HP1 contract and one of the six a4/a8, DIM16/32/64 profiles. The C API rejects shapes and run views outside its hardware capacities; the base and production run-aware certificates bind the broad single-work geometry and residual domain. FULL and residual host work use slot 0; PIPELINE stripes may use slots 0 and 1.

Reference backing timing is explicit: read delay 3, even-ID delay 13, scale-read extra delay 17, write delay 11, backing offset 5. Dense traces may use read-ready period 3 or 5. Residual traces require period 5, matching the production run-aware certificate. Initial buffer halves are each 0 or 1. Other timing, concurrent work, custom memory providers, and unbound binaries are rejected.

The RTL source gives the drained transition: the bridge emits final `logicalDone` after controller, memory, and scale-loader busy state clears. `UpstreamWsHp1Top` frees the host slot only after loop completion and every scale release. With one outstanding work, the new probe checks `busy=false`, `memoryDrained=true`, `writebackDrained=true`, no controller busy, and empty backing read/write queues at that reusable boundary. The software service result is compared to the RTL result, final scale release, and resource-ready cycle. The probe also retains exact numerical output assertions and per-cycle scale-release checks from the existing service harness.

The service model carries buffer ownership and the global core cycle into the next work. `HostCommandBridge` starts command configuration at index 0 when the issued queue is empty; `ScaleBackingLoader` resets its row index and column when it dequeues the new descriptor. Memory drain waits for active read contexts, store completion, response pulses, and accumulator settling. These source conditions support reuse after a fully drained boundary across admitted shapes; the finite sequence corpus checks representative transitions and does not replace those source conditions.

The independently pinned corpus has 176 guarded observations per profile: five two-work sequences over periods 3 and 5, every acceptance phase, reset and continuous cases, plus a K32-primed residual-to-dense pair. The primer reaches the `(scratchpad=1, accumulator=0)` state that DIM64 K64 alone cannot reach. All four initial-half combinations are observed at each tested phase. Across six profiles there are 1,056 guarded observations. These use fixed 2×3 dense/residual fixtures, not the actual llama producer's three-stripe and residual-child sequence. They test the structural drained invariant but do not establish exact service timing for those production sequences, arbitrary state, a physical clock, or whole-model latency. Production admission requires a separately bound producer-generated same-instance sequence/phase corpus.

The older boundary report also records `release_mismatches`: it compares the non-draining cycle estimate's last scale-release event to the RTL's post-result final release. That diagnostic count is expected to be nonzero. The service certificate requires the draining API's `model_service_release` and `model_resource_ready` to match RTL exactly; its service mismatch count is zero.

`sim/tests/cycle/service_certificate_build.py` regenerates the artifact from verified current RTL objects and the exact library/base/run certificate paths. It writes only after all profile observations validate. The artifact stores content hashes, not a third-party signature. A fixture `ServiceAdmission` retains those hashes for diagnostic estimates; it cannot authorize `RECONSTRUCTED` scheduling. Future schedule publication must bind a production-scope certificate and retain its exact input artifacts for later audit.

The additive `PRODUCTION_GENERATED_SEQUENCE` version 2 certificate references that separate version 1 fixture artifact. Its checked-in `sim/cycle/production_sequence_corpus.json` independently pins six producer traces, lifecycle logs, semantic graphs, source receipts, and 30 four-work period-five phase cases. The builder in `sim/cycle/production_sequence_certificate.py` accepts an input JSON document with `cases` entries containing `profile`, a four-integer `phases` array, and an absolute `report` path. It also requires `--library`, `--base-certificate`, `--run-certificate`, `--fixture-certificate`, and a new `--out` file. The builder writes only after all 30 reports pass independent raw validation.

For each case the validator reprojects the exact producer work and ownership from the trace, lifecycle, and semantic graph, compares the numeric RTL input to that projection, verifies the official RTL build and compiled probe, and recomputes C-service endpoints, counters, and selected events from the bound library. It checks one reset and one RTL instance, per-work result, final scale release, resource readiness, carried halves, numerical output, and either physically empty internal queues or a separately bound `INERT_WS_TAG_CARRY` proof. The tag-carry proof binds the raw RTL log and source hashes, checks the garbage head and next dequeue, verifies ID wrap, and rules out queue-capacity backpressure. It never describes a nonempty queue as empty. The provider admits only an entire certified ordered work/phase/half vector; a fixture certificate, scope string, partial case set, or separately mixed phase rows cannot enable reconstructed scheduling.

The first same-instance A4D16 observation had exact public endpoints and counters but left one mesh tag queue entry at public resource readiness. Its historical `OBSERVED_UNDRAINED` report remains rejected. A current-source `im2p-inert-ws-tag-carry` proof must show an invalid garbage head, enqueue/dequeue conservation, no cumulative queue growth or full-queue stall, matching next-work dequeue, valid first output tag, and exact service/numerical results. The queue is not physically empty. Only a validated version 2 certificate for the pinned four-work producer trace, period-five phase vector, and initial halves `(0, 0)` grants `CURRENT_CERTIFIED_SEQUENCE`; it does not admit other traces, arbitrary mixed phases, or paper latency without a separate operating-clock artifact.
